# EIP-7702 智能账户存款指南

TokenBank 的第三种存款方式：利用 **EIP-7702**（Pectra / Prague 硬分叉引入的 EOA 可编程性），让用户将 EOA 委托给 **MetaMask 官方 Delegator 合约**，并在**一笔交易**内完成「委托 + ERC20 授权 + 存款」。

- MetaMask Delegator 地址（主网/Sepolia 等链统一）：`0x63c0c19a282a1B52b07dD5a65b58948A07DAE32B`
- 合约层零改动：7702 委托发生在交易协议层，`TokenBankPermit` 的 `deposit()` 语义完全兼容。

## 一、原理简述

### Type-0x04 交易

EIP-7702 引入新的交易类型 `0x04`，比普通交易多一个 `authorization_list` 字段：

```
Type-0x04 交易:
  from              = 用户 EOA
  to                = 用户 EOA（自调用）
  authorizationList = [EOA 签名的授权 → 委托至 0x63c0...32B]
  data              = execute(BatchDefault, abi.encode(Execution[]))
```

### 委托设计器（Delegation Designator）

交易执行前，EVM 先处理 `authorization_list`：将 EOA 的 code 设置为

```
0xef0100 || <delegate 地址>     （共 23 字节）
```

此后该 EOA 的每次调用都会执行 delegate 合约的代码，但地址、nonce、余额保持不变——对 TokenBank 而言 `msg.sender` 仍是 EOA 地址。

### MetaMask Delegator 的批量执行接口

Delegator 实现 ERC-7579 风格的 `execute()`：

```solidity
function execute(bytes32 _mode, bytes _executionCalldata) external payable;
// BatchDefault mode = 0x0100...0000
// _executionCalldata = abi.encode(Execution[])
// Execution = { address target; uint256 value; bytes callData; }
// 权限：仅 EOA 自身（onlySelf）或 EntryPoint 可调用
```

### 执行顺序（单笔交易、原子）

1. 协议处理 `authorization_list` → EOA code 变为 `0xef0100 || 0x63c0...32B`
2. 交易 data 被路由到 Delegator 执行 → `onlySelf` 校验通过（`to == from == EOA`）
3. Delegator 依次执行 `Execution[0] = approve(tokenBank, amount)`、`Execution[1] = deposit(amount)`
4. `deposit()` 中 `transferFrom(msg.sender=EOA, ...)` 因上一步 approve 而成功

任一步失败则整笔交易回滚（原子性）。

### 授权 nonce 规则

当交易发送者 == 授权者（EOA 自付 gas 自调用）时，`authorization.nonce = 账户当前 nonce + 1`。MetaMask 与 viem（`executor: 'self'`）均会自动处理。

## 二、DApp 集成方式（重要）

**MetaMask 不向 DApp 暴露 `signAuthorization`**——7702 授权签名仅在钱包内部完成，且委托目标限制为官方白名单（含 `0x63c0...32B`）。

DApp 侧的正确路径是 **ERC-5792 `wallet_sendCalls`**（wagmi `useSendCalls`）：

```ts
sendCalls({
  calls: [
    { to: TOKEN,     data: encodeFunctionData(approve(TOKENBANK, amount)) },
    { to: TOKENBANK, data: encodeFunctionData(deposit(amount)) },
  ],
});
```

用户在 MetaMask 中开启智能账户后，钱包自动：
1. 检测到多笔 calls 需要原子执行 → 构造 Type-4 交易
2. 若账户尚未委托 → 在 `authorization_list` 中加入委托至官方 Delegator 的授权（钱包内部签名）
3. 提交一笔交易，DApp 通过 `wallet_getCallsStatus` 轮询结果

viem 直签路径（`signAuthorization` + `sendTransaction({ authorizationList })`）仅适用于本地私钥账户，用于自动化验证（见第五节 e2e 脚本），**不适用浏览器 MetaMask**。

## 四、本地 fork Sepolia E2E（脚本级验证，无需 MetaMask）

MetaMask Delegator 只存在于真实链（主网/Sepolia 等）。本地 Anvil（31337）上没有，因此用 fork 方式做**脚本级**验证（不需要 MetaMask）：

> **为什么浏览器 MetaMask 验证不能用本地 fork？**
> MetaMask 添加自定义网络时 Chain ID 由 RPC 端点自动检测，无法手动指定；本地 fork 的 chainId 为 `11155111`，与 MetaMask 内置的 Sepolia 网络冲突，无法添加。因此**浏览器验证请使用真实 Sepolia（见第五节）**。

### 1. 启动 fork 节点

```bash
export SEPOLIA_RPC_URL=https://ethereum-sepolia-rpc.publicnode.com   # 或自有 RPC
anvil --fork-url $SEPOLIA_RPC_URL
# fork 保留 chainId 11155111，且 0x63c0...32B 上有真实 Delegator 字节码
```

### 2. 部署合约

```bash
cd contracts

# Anvil 默认账户 0（自带 ETH）
export PRIVATE_KEY=0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80
export INITIAL_SUPPLY=1000000

forge script script/Deploy.s.sol --rpc-url http://127.0.0.1:8545 --broadcast
```

部署日志应显示 `EIP-7702 delegator detected: ready for 7702 flow`。

### 3. 脚本级验证（无需 MetaMask）

```bash
cd frontend

RPC_URL=http://127.0.0.1:8545 \
PRIVATE_KEY=0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80 \
TOKEN_ADDRESS=<部署的token地址> \
TOKENBANK_ADDRESS=<部署的bank地址> \
node scripts/e2e-7702.mjs
```

脚本断言：交易为 EIP-7702 类型（`eip7702`/`0x4`）、存款入账、allowance 归零、EOA code 为 `0xef0100 || 0x63c0...32B`。输出 `PASS` 即通过。

## 六、安全说明

- **委托是持久状态**：`0xef0100 || delegate` 会一直存在，直至下一次 7702 交易重新授权（授权到 `0x0` 地址可撤销委托）。撤销后 EOA 恢复纯外部账户行为。
- **Delegator 权限模型**：MetaMask Delegator 为 stateless + onlySelf——只有 EOA 自身（或 EntryPoint）能触发 execute，第三方无法代调用（回归测试 `test_7702OnlySelfRejected` 验证）。
- **钓鱼风险**：7702 批量交易让"一笔交易做多件事"成为可能，用户确认前应仔细核对钱包中展示的完整调用列表。本项目批量内容固定为 `[approve(精确金额), deposit(精确金额)]`，approve 即用即销（回归测试 `test_7702BatchIsAtomic` 验证失败时 approve 一并回滚）。
- **MetaMask 白名单保护**：MetaMask 仅允许委托至官方审核的 Delegator 合约，DApp 无法诱导委托到任意地址。

## 七、常见问题

| 现象 | 原因 / 解决 |
|---|---|
| 按钮禁用并提示不支持 atomicBatch | MetaMask 未开启智能账户：账户详情 → 升级后重试（或刷新页面重新检测 capabilities） |
| `MetaMask Delegator not found` / 脚本 prelight 失败 | 目标链上没有 `0x63c0...32B`：本地链需改为 fork Sepolia，或改用真实 Sepolia |
| 无法把本地 fork 添加到 MetaMask | 预期行为：自定义网络的 Chain ID 由 RPC 自动检测，fork 的 `11155111` 与内置 Sepolia 冲突。浏览器验证请用真实 Sepolia（第五节） |
| 交易回滚但余额未变 | 原子性生效：批量中任一调用失败（如余额不足），approve 也一并回滚 |
| 委托后普通存款/取款异常 | 不会发生：委托不改变 `msg.sender`，回归测试覆盖 permitDeposit 与两步流程 |
| nonce 相关授权失败 | 发送者即授权者时 nonce 需为「当前 nonce + 1」；使用 viem `executor: 'self'` 或让 MetaMask 处理 |
