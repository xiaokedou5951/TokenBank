# TokenBank 系统架构概览

## 1. 目标

描述 TokenBank 的整体系统分层、模块边界、部署拓扑以及主要数据流，帮助读者建立全局视图。

## 2. 关键结论

- TokenBank 采用经典的两层 DApp 架构：**链上合约层** + **浏览器前端层**。
- 合约层包含 `MyToken`（支持 EIP-2612 的 ERC20 代币）、`TokenBankPermit2`（支持 Permit2 存款的银行合约）和 **Uniswap Permit2**（签名授权转账，独立部署），无管理权限。
- 前端为纯客户端渲染（`'use client'`），通过 RainbowKit 连接钱包，通过 Wagmi Hooks 读写链上数据。
- 前端支持两种存款模式：传统 Approve+Deposit（两步交易）和 Permit2 Deposit（Uniswap Permit2 签名，一步完成）。
- 所有业务状态均来自链上查询，前端不依赖任何自建后端服务。

## 3. 系统分层

```
┌─────────────────────────────────────────────────────────────┐
│                        浏览器前端层                          │
│  Next.js 16 (App Router) + React 19 + Tailwind CSS 4       │
│  RainbowKit（钱包连接）→ Wagmi / Viem → 合约调用             │
│  存款方式：Approve+Deposit（传统） / Permit2 Deposit（签名） │
└───────────────────────────┬─────────────────────────────────┘
                            │ JSON-RPC / Wallet Provider
┌───────────────────────────▼─────────────────────────────────┐
│                        链上合约层                            │
│  MyToken.sol（ERC20 + EIP-2612 Permit 代币）          │
│  TokenBankPermit2.sol（代币存取合约，支持 depositWithPermit2）│
│  Permit2（Uniswap Permit2 合约，签名授权转账）               │
└─────────────────────────────────────────────────────────────┘
```

## 4. 模块边界

| 模块 | 职责 | 边界说明 |
|------|------|----------|
| MyToken | ERC20 + EIP-2612 代币实现 | 负责余额、转账、授权（approve/permit）、nonce 管理 |
| TokenBankPermit2 | 代币存取托管 | 持有用户存入的代币，记录存款余额，支持传统存款和 Permit2 存款 |
| Permit2 | Uniswap Permit2 合约 | 提供签名授权转账能力，管理用户 nonce bitmap |
| 前端 Hooks (`useToken` / `useTokenBank`) | 封装合约调用 | 不直接操作 UI，只暴露数据和操作函数 |
| 前端组件 | UI 渲染与用户交互 | 不直接调用合约，依赖 Hooks 提供的数据和行为 |
| Wagmi / RainbowKit | 钱包连接与链交互 | 屏蔽不同钱包和链的差异 |

## 5. 部署视图

当前支持三种运行环境：

| 环境 | 链 | RPC | 用途 |
|------|-----|-----|------|
| 本地开发 | Anvil（chainId 31337） | `http://127.0.0.1:8545` | 本地联调 |
| 测试网 | Sepolia | Ankr RPC | 测试验证 |
| 主网 | Mainnet | Ankr RPC | 生产访问（配置中预留） |

合约地址通过前端环境变量注入；本地开发使用 Anvil 默认地址作为 fallback。

部署脚本 `DeployPermit2.s.sol` 独立部署 `Permit2` 合约，`Deploy.s.sol` 从环境变量读取 `PERMIT2_ADDRESS` 后依次部署 `MyToken` → `TokenBankPermit2`，并将代币地址和 Permit2 地址注入银行合约。本地部署脚本 `deploy-local.sh` 按顺序执行：先部署 Permit2 并将地址写入 `contracts/.env`，再部署其余合约。

## 6. 核心数据流

### 6.1 读取余额

```
用户打开页面 → BalanceCard 挂载
                    ↓
            useTokenBalance / useDepositBalance / useTokenAllowance
                    ↓
            Wagmi useReadContract → JSON-RPC → 合约 view 函数
                    ↓
            React Query 缓存 → UI 渲染
```

### 6.2 传统存款流程（Approve + Deposit）

```
用户输入金额 → DepositForm 调用 useApprove().approve()
                    ↓
            钱包签名授权 TokenBankPermit 花费代币
                    ↓
            用户再调用 useDeposit().deposit()
                    ↓
            钱包签名 → TokenBankPermit.deposit() → transferFrom → 更新 balances
                    ↓
            交易确认后 invalidateQueries → 刷新余额
```

### 6.3 Permit2 存款流程（一键签名存款）

```
用户输入金额 → DepositForm 调用 handlePermit2Deposit()
                    ↓
            读取 nonceBitmap → 计算下一个可用 nonce
                    ↓
            构建 EIP-712 typed data（PermitTransferFrom）→ signTypedDataAsync()
                    ↓
            钱包弹出 EIP-712 签名请求 → 用户签名
                    ↓
            depositWithPermit2(permitTransfer, owner, signature)
                    ↓
            TokenBankPermit2.depositWithPermit2()
              → permit2.permitTransferFrom() 验证签名并转账
              → balances[owner] += amount
              → emit Permit2Deposit
                    ↓
            交易确认后 invalidateQueries → 刷新余额
```
